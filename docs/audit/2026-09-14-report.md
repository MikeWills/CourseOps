# CourseOps audit, 2026-09-14

Eight independent reviews of the code at `main` (e4f389c): one security, one
code-quality/performance, and six traceability passes, one per hop
(live-map client -> API, setup client -> API, live routes -> modules, setup
routes -> modules, SQL -> schema, server payloads -> client). Raw reports
with every file:line and the full control/route/statement inventories are in
`2026-09-14-raw/`. The work list derived from this is `2026-09-14-tasks.md`.

Nothing in the repo was changed. Nine findings were reproduced against a
scratch database with the FastAPI test client.

## The one-paragraph version

The plumbing is sound: every button reaches a real route with the right
method and body, all 236 SQL statements compile against the schema with the
right placeholder counts, migrations reproduce the current schema from every
historical version, SQL is parameterised everywhere, both clients escape
consistently, and role gating of the snapshot and socket holds. What the
reviews found instead is a small number of real defects on paths the tests
do not cover: **one way to crash the server from the setup screen**, three
cross-event holes that matter the day a second club is hosted, a login
endpoint that can freeze the live map, a roster edit that duplicates a
station, and a handful of client bugs where a feature silently stopped
working after a refactor (CSV coordinates, the focus-the-bib step, layer
switches after a resync). Below that is a long tail of hygiene.

## Critical

**C1. Turning tracking on for an event with no roster and no course exits
the server, and it boot-loops.** `run_ingest` signals "cannot start" with
`SystemExit`; `_supervise_ingest` catches `Exception` only, so it escapes the
event loop and uvicorn stops. The switch is persisted *before* the task is
started, so systemd restarts into the same crash. An officer who creates an
event and flips Tracking before importing the course takes every role page
down; the only fix is editing the database. Same path if a deploy's `.env`
loses the callsign while an event is flagged. (web.py:2142-2155,
ingest.py:179-198, web.py:1083-1091. Found by TR3-1, TR4-1, OPT-1.)

## High

**H1. Staged import features are addressed by id only.** `/assign` on event
A accepts feature ids from event B: copies B's organizer geometry into A and
marks B's features assigned/discarded. Ids are a global autoincrement. Also
the poi branch never checks the layer exists, against the documented rule.
(importer.py:173-176, 268, 342, 376. SEC-1, TR4-4, TR5-3, SEC-17.)

**H2. Link revoke and relabel are by id with no event check.** An admin of
one event can revoke another event's NCS/SAG links on race morning; the
victim sees 404s and nothing else. (access.py:223-239, web.py:1359-1377.
SEC-2, TR4-2.)

**H3. Login runs scrypt synchronously on the event loop, unauthenticated,
unthrottled.** Measured 0.6 s per attempt (1.2 s for an unknown username -
the "dummy hash" does two hashes, so it also leaks which usernames exist).
Two requests a second from anyone freezes WebSocket fan-out and `/state` for
every phone; on the phones it looks like bad signal. (web.py:685-700,
users.py:393-406. SEC-3, SEC-7.)

**H4. Editing a roster entry's callsign in setup produces two roster rows.**
`change_station_key` deliberately *binds* rather than renames for
bare->SSID and cross-callsign cases; `save_roster_entry` then upserts under
the new key and inserts a second row. Reproduced. No test covers the path.
(admin.py:562-571, db.py:641-708. TR4-3, TR5-1.)

**H5. Station status broadcasts miss every bound roster entry on other
screens.** The socket message carries the roster key; the client keys its
map by tracking key. The operator who pressed the button sees it (optimistic
update); the other two NCS screens and Logistics do not. (web.py:1729,
app.js:2472/2546. TR1-1, TR6-1.)

**H6. Reconnect dies for good if the phone is still offline when the retry
fires.** `loadState()` has no try/catch; the rejection inside the
`setTimeout` callback stops the loop. Badge reads "Connecting..." forever.
Related: any non-2xx reads as "Access denied" (a 502 during deploy), and the
snapshot is fetched *before* the socket subscribes so anything published in
the gap is lost. (app.js:2376-2387, 2575-2586. TR1-2, TR6-2, TR6-8, TR6-10.)

**H7. Places CSV export writes an empty Coordinates column.** The exporter
reads `.coords span`; #108 replaced the span with two inputs. The banner
still says "Exported N places". (setup.js:2114 vs 1130. TR2-1, TR6-3.)

**H8. A wrong password shows "Sign in again."** `api()` intercepts every 401
as session-expired before reading the server's message; a disabled account
is told to sign in again forever. (setup.js:51. TR2-2.)

**H9. `raw_packet` stores raw text from stations the roster does not know.**
Parse failures and no-position packets (status, messages, telemetry from the
public near the course) are logged *before* the roster check, contrary to
the "not even raw" rule the area filter is allowed under. Nothing reads the
table; it grows forever and is in the nightly backups. (ingest.py:178-190.
SEC-5, TR5-2, OPT-7.)

**H10. All 86 routes do synchronous SQLite work on the event loop; `/state`
costs ~180 ms on the demo event and scales with places x course vertices.**
88 % is `CourseIndex.locate`, called 4x per place with no memo. Every read of
layers/leaders also issues `INSERT OR IGNORE` writes, taking the WAL write
lock inside a snapshot - proven to block for the full busy timeout against a
concurrent writer. Twelve phones resyncing after a setup save serialise into
seconds of frozen fan-out. (web.py:456-460, progress.py:156-163,
categories.py:129-146. OPT-2, OPT-3, OPT-4.)

**H11. A `dropped_off` pickup draws on the map as a white-on-white square.**
`.inc--dropped_off` has no CSS rule; only `closed` markers are removed. List
and map have drifted, which CLAUDE.md names as the bug to avoid.
(app.css:913-920, app.js:1864. OPT-17.)

## Medium

Grouped by area. IDs match `2026-09-14-tasks.md`.

Security and privacy
- **M1** CSRF on the setup API is `SameSite=Lax` alone; no Origin check, any
  Content-Type parsed. Two GETs mutate (`/links` creates tokens,
  `/categories` seeds). (SEC-4, SEC-13)
- **M2** Role tokens land in Apache access logs on every request and in the
  journal on every restart (`cmd_serve` prints the links). (SEC-6)
- **M3** No request-body cap: a large POST to `/login` needs no credential;
  the import reads the whole upload into RAM before the KML caps apply.
  (SEC-8)

Ingest
- **M4** Ignore does not take effect until an *unknown* station happens to
  beacon - membership refreshes only on unknown packets. The ignored igate
  reappears on every screen after its next beacon. Also the first packet after
  an adopt is discarded rather than stored. (TR3-2, TR6-6, TR3-8)
- **M5** Starting a second event's feed leaves the first flagged on; on
  restart the lower-id one is started then killed. Deleting an event never
  stops its feed. (TR3-3, TR4-5)

Data integrity
- **M6** No transactions anywhere: `db.connect` is autocommit, the 18
  `conn.commit()` calls are no-ops, and `create_poi` commits the row before
  validating W3W/course ids (a 400 after the insert). `assign_course`,
  `change_station_key`, reorders and event delete are all N separate
  transactions. (TR4-6, TR4-7, OPT-15)
- **M7** Renaming `N0CALL-1` to `N0CALL-7` leaves the status log under the
  old key; the per-station handover log goes blank. (TR5-4)
- **M8** Deleting a place cascades away every lead-runner sighting at it,
  silently; layers refuse with a count, places do not. (TR5-5)

Live map client
- **M9** A resync never re-renders the layer switches: a layer added on race
  morning has no switch, a renamed one keeps its old name. (TR1-4, TR6-4)
- **M10** The "cursor straight into the bib field" step after dropping a pin
  has been dead since #93 renamed the attributes. (TR1-3, TR6-5)
- **M11** Leader Undo/Clear ignore `response.ok`; six setup handlers (delete
  course/place, remove roster entry, issue/label/revoke/reissue link) have no
  catch, so a 4xx does nothing on screen; import shows "Unexpected token <"
  on a proxy error page. (TR1-5, TR2-5, TR2-9)
- **M17** A subscriber whose queue overflowed never learns what it missed - a
  deleted pickup stays on that phone with the badge reading "Live". Whether
  the deployed WebSocket backend sends pings is unverified. (TR6-7, OPT-9,
  OPT-U1)
- **M18** The SSID panel is rebuilt on every `nearby` packet with no
  field-edit capture; the "This is..." dropdown snaps shut under NCS's thumb.
  (TR6-9)
- **M19** Every setup row saved is one `resync`, and every resync is one full
  `/state` + Leaflet rebuild on every phone with no debounce. Twelve renames
  = twelve snapshots per phone. Multiplies H10. (OPT-8)

Setup client
- **M12** "New version - reload" shows falsely after signing in from a
  signed-out page (`build` is empty pre-login). Cries wolf on every deploy.
  (TR2-3)
- **M13** Courses is the one table still on per-row Save + full reload - the
  exact pattern that cost twelve renames. (TR2-4, TR6-15)
- **M14** `S.poiCategories` is cached across events: switch events and the
  Places/Import/Move dropdowns show the previous event's layers. (TR2-6)
- **M15** Table containers get another set of drag/input listeners on every
  re-render; after twenty saves one drag posts twenty reorders and twenty
  resyncs. (TR2-7)
- **M16** No UI sets an event's centre, so the picker's fallback for a
  parade (#108) opens on the whole US; `suggest_event_center` has no caller.
  (TR2-8, OPT-6)

Structure
- **M20** `create_app` is 1801 lines holding bootstrap, setup API, field API,
  socket, guides and ingest lifecycle. Splitting it is what makes
  `require_access` a `Depends`, removes 106 hand-written `conn.close()` and
  38 unused `user` unpackings. Effort L. (OPT-13)

## Low

Fourteen groups; detail and lines in the task file. The headlines: JSON
values of the wrong type become 500s on ~12 routes; division keys are
neither validated nor consistently normalised; ~20 dead functions and the
retired `admin_token` table; no CSP and Leaflet from unpkg; layer colour and
icon validated only client-side; deploy workflow interpolates the tag into a
shell line and re-learns the host key each run; temp-dir leak per upload;
first-run bootstrap open to whoever reaches `/setup` first; MAX(symbol_table)
paired with MAX(symbol_code) from different packets; `changed_by` truncated
to 12 in one log and 24 in the others; four copies of the reorder routine,
three of the taxonomy routes, nine hand-rolled POSTs in app.js; N+1 counts on
the setup lists; a `last_used` write on every field request.

## What was checked and found clean

Worth knowing so nobody re-checks it:

- Every client control reaches a declared route with matching method, path
  and body keys; literal routes precede parameterised ones; no typo'd ids.
- All 236 SQL statements compile against the schema; placeholder counts
  match; `_ADDED_COLUMNS` reproduces the current schema from all 17
  historical schema commits and every tag; FKs on, cascades as documented.
- Every live-token write passes `require_capability` and filters on
  `granted.event_id`; invalid token 404, unprivileged 403; snapshot and
  socket gating of incidents/nearby/ignored by capability holds; Staff gets
  neither.
- SQL parameterised everywhere; `defusedxml` is the only XML parser; KMZ
  caps; `escapeHtml`/`esc` on every interpolation in both clients; the
  guides renderer escapes; `/help/{page}` is regex-gated; `/healthz` minimal.
- scrypt with per-hash salt, `compare_digest`, `token_urlsafe(32)` sessions,
  `HttpOnly`/`Lax`/`Secure`; role tokens 192-bit.
- Deploy: forced-command validator, exact sudoers, hardened unit, no secrets
  echoed, version/tag check.
- Timestamps one format everywhere; metric storage honoured; row->dict
  helpers consistent with readers.
- No dead JS functions; one orphan CSS class; no mutable defaults, no TODOs.
- Reconnect backoff, capability strings, `waiting_count` definition,
  `captureFieldEdit` coverage (except the SSID select).
