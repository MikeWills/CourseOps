## Rules for whoever picks a task

1. Read `CLAUDE.md` first, especially "Domain rules" and "Working method".
2. One task (or one clearly marked group) per branch and PR. Branch name:
   `fix/<slug>` or `chore/<slug>` as given. Never push to `main`.
3. Mark the task `[~]` here with your branch name when you start, `[x]` with
   the PR number when the PR is open. Two agents on one task is waste.
4. Tasks in the same **workstream** touch the same files - do not run two of
   them in parallel. Tasks in different workstreams are safe to parallelise.
5. Every fix ships with a test that fails before and passes after (the
   agent reports say what to assert), a `CHANGELOG.md` entry under
   `[Unreleased]` saying what broke and why it mattered, and the guides /
   RUNBOOK / CLAUDE.md updates the working-method table requires. If the
   fix reveals a trap, add the domain rule.
6. Run `./.venv/Scripts/python.exe -m pytest -q` before opening the PR.
7. If the task is wrong, out of date, or bigger than its estimate, say so in
   the PR rather than quietly narrowing it.

Effort: S < 1 h, M 1-3 h, L half a day or more.
